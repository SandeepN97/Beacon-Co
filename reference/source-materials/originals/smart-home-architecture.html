STAGE 01 / HARDWARE & TOPOLOGY

Decide what runs where, before buying anything

Every version of this build so far assumed one Pi runs Home Assistant, Frigate, and Ollama together. That's a real, working setup — but it's a budget compromise, not the best option, and it's worth deciding on purpose rather than by default.

One Pi does everything
Split: Green + a second box
Add a Zigbee/Thread coordinator
A Pi 5 (8GB), active cooler, USB SSD boot instead of microSD, and a proper 27W supply. Documented benchmarks show it runs Home Assistant plus light add-ons comfortably around 40–55% RAM at idle — Frigate with even one camera is where it starts to feel squeezed, and local voice transcription gets frustratingly slow on top of that. Cheapest path, most fragile under load.
Home Assistant Green ($149–199, Rockchip RK3566, 4GB RAM, 32GB eMMC) is now Nabu Casa's only official hub — Yellow was discontinued in October 2025. Green is plug-and-play, idles at roughly 4–6W, and its soldered eMMC storage doesn't wear out and corrupt the way SD cards do. It has no camera or LLM headroom to spare, though — the documented pattern that keeps coming up: "the Green handles the automation, a second box handles the video." Put Frigate (and Ollama, if running locally) on a separate Pi 5 or small mini PC instead of asking Green to do all three jobs.
None of your current devices are Zigbee, but it's worth flagging now rather than after the fact: adding a Home Assistant Connect ZBT-2 dongle (Zigbee + Thread/Matter in one) gives any future device a fully local path that doesn't depend on a vendor's cloud at all — a stronger fix than segmenting cloud devices after buying them.
STAGE 02 / CORE STACK

Install the brain

Home Assistant is the hub every device reports to. Mosquitto brokers anything that talks MQTT. None of this needs to leave the Pi.

Field researchThe Pi-only Ollama setup from the last version undersold a real constraint. A widely-shared NetworkChuck video runs Ollama on a separate Mac Mini instead of the Pi — and the Home Assistant community thread reacting to it confirms why: Pi CPU inference is workable but slow. Two honest paths, below.
Path A — Pi only
Path B — offload Ollama
AI HAT+ 2 middle ground
Gemma 3 1B runs ~18–22 tok/s on Pi 5 CPU — fast enough to feel responsive. Phi-3 Mini 3.8B is smarter but drops to ~4–7 tok/s. 7B+ models are impractical on CPU alone. Fine for a first build.
Point Home Assistant's Assist pipeline at Ollama running on any spare machine with 8GB+ VRAM on your LAN — a Mac Mini, an old gaming PC, anything with a real GPU. The Pi then only runs Home Assistant plus the voice satellite. This is what most serious builds actually do once they outgrow the Pi-only setup.
The official AI HAT+ 2 (Hailo-10H, 40 TOPS INT4) runs a compatible hailo-ollama server that mirrors the standard Ollama API, giving roughly 5–10x the inference speed of CPU-only — without needing a second machine.

STAGE 04 / SEQUENCE — LITTER AUTOMATION

What happens, in order

Frigate runs locally and watches a defined zone over the litter area — "cat" is already in its default detection model. Documented builds consistently tune three things: detect at 1280×720 rather than the camera's native 4K (a 60% CPU cut with no real accuracy loss), run detection at 5fps instead of 30fps, and draw the zone as a tight polygon rather than trusting the whole frame. STAGE 05 / SEQUENCE — VOICE COMMAND

What happens when you ask for something

Correction from the last version: not every request should hit the LLM. Home Assistant's built-in intent engine resolves simple, well-formed commands — "turn off the kitchen lights" — in a few hundred milliseconds without touching Ollama at all. Only phrasing the intent engine can't parse falls through to the model, which then reads the memory store for context before deciding what to call. This is the actual documented behavior of the Assist pipeline, not a simplification.

STAGE 06 / NETWORK & SECURITY

Segment before you automate

Put every cloud-linked device — Alexa, Pura, the purifier — on its own VLAN so a compromised device can't reach your laptop or NAS. Run Pi-hole or AdGuard Home on a second lightweight Pi so a Home Assistant reboot doesn't take DNS down for the house. Never port-forward Home Assistant — use a WireGuard-based mesh like Tailscale for remote access instead.

Three corrections from the last version, all documented failure modes other builders hit first:

Device discovery breaks
DNS bypasses Pi-hole
HA can't reach the IoT VLAN
VLANs isolate broadcast domains, which is the point — but Govee's app pairing, Chromecast, and Sonos all rely on mDNS to find devices, and mDNS doesn't cross VLANs by default. Run an mDNS reflector (Avahi, or your router/UniFi controller's built-in option) between the Trusted and IoT VLANs specifically for discovery traffic.
One documented setup lost a week of protection this way: a smart TV had 8.8.8.8 hardcoded and simply ignored the DHCP-assigned Pi-hole address. Block outbound UDP/TCP port 53 from the IoT VLAN to anywhere except your Pi-hole's IP — don't just set it as the suggested resolver.
Segmentation done correctly blocks Trusted-to-IoT traffic by default — which also blocks Home Assistant from reaching your devices, since HA usually lives on the Trusted side. Add one explicit allow rule: Home Assistant's IP, and only that IP, to the IoT VLAN. Everything else on Trusted stays blocked from IoT.
Security noteKeep every token and password in Home Assistant's secrets.yaml, never inline in automation files — it's the difference between a leaked config and a leaked credential.
STAGE 07 / POWER & BACKUP

What happens when the power actually goes out

None of the previous versions addressed this at all, and it's not optional for something that now controls your cat's litter box and your air quality. A UPS on its own only buys time — the part that matters is monitoring it and reacting before the battery dies.

What goes on the UPS
Graceful shutdown, not a hard stop
Backups you can actually restore
Router, modem, switch, the Home Assistant host, and any Zigbee/Thread USB dongles — all on the UPS. Monitor it with NUT (Network UPS Tools) and Home Assistant's official NUT integration, which reached Home Assistant's "platinum" quality bar in the 2025.9 release. Skip the vacuum, purifier, and diffuser — a small UPS isn't sized for them, and losing them briefly during an outage is fine.
Set an automation on the UPS battery-percentage sensor: at a threshold like 30%, trigger a clean Home Assistant shutdown rather than waiting for a hard cutoff — this is what protects the database from corruption. A second, lighter automation can shed load the moment power is lost at all: turn off non-essential lights and plugs to stretch the runtime for the router and Zigbee mesh specifically.
Home Assistant's built-in backup system does scheduled, encrypted backups to a location you pick. The only real failure mode is not testing it — restoring to fresh hardware takes about ten minutes if backups have actually been running, and considerably longer if you're finding out they weren't. Unplug the UPS from the wall every few months to confirm the whole chain — detection, shutdown automation, restart — actually fires.
STAGE 08 / PERSONALIZATION

Let it remember the house, not retrain itself

Fine-tuning the model's weights on daily usage isn't realistic on a Pi, and isn't the right tool anyway. The memory store shown in the sequence diagram above — routines, preferences, the cat's usual schedule — is what actually gives the felt sense of a system that's learned your house.

HOW IT ALL COMES TOGETHER

The build order

Everything above described individually. This is the actual sequence — network first, hub second, devices one at a time, automation and safety nets last — with every device you own placed where it belongs.

  1. Choose topology and buy hardware

    One Pi 5 (8GB) doing everything, or Home Assistant Green for the hub plus a second Pi 5/mini PC for Frigate and Ollama. Either way: active cooler, USB SSD (not microSD), a real 27W supply.

  2. Build the network before anything connects to it

    Managed switch with 802.1Q support, a Trusted VLAN and an IoT VLAN, an mDNS reflector between them, and outbound DNS (port 53) from the IoT VLAN locked to your future Pi-hole's address only.

  3. Stand up Home Assistant and turn on backups immediately

    Flash Home Assistant OS on the hub. Before installing a single integration: Settings → System → Backups, set an automatic encrypted schedule. This is the step every "I lost everything" thread has in common skipping.

  4. Install Mosquitto and Pi-hole/AdGuard Home

    Mosquitto for MQTT. Pi-hole or AdGuard Home on its own lightweight second Pi so a hub reboot never takes the house's DNS down with it. Point the IoT VLAN's DHCP at it.

  5. Bring the Govee light online

    Native Govee integration; enable the local LAN API in the Govee app if your model supports it.

    → Govee light

  6. Flash the Arduino

    ESP32/ESP8266: flash ESPHome for native local integration. Classic Uno/Mega: wire it to report over MQTT to Mosquitto instead.

    → Arduino

  7. Pair the Echo devices

    Both Echos onto the IoT VLAN. Install Alexa Media Player (HACS) so Home Assistant can see and control them. They stay peripherals — voice recognition never leaves Amazon's cloud.

    → Echo Show, Echo Dot

  8. Connect Pura and the air purifier

    Pura via its unofficial HACS integration — accept that it's cloud-only, there's no local API. Check the purifier for Tuya local-mode support before falling back to its cloud integration.

    → Pura diffuser, air purifier

  9. Attempt to root the vacuum

    Check valetudo.cloud's current supported-model list for your exact Dreame X model before buying into "fully local." If it's supported, root it for local per-zone control. If not, the stock cloud integration still gives room-by-room cleaning.

    → Dreame X vacuum

  10. Install Frigate and point it at the litter camera

    Detect at 720p/5fps, not native 4K. Draw a tight zone polygon over the litter area — "cat" is already in the default model. Add a Coral USB accelerator if this Pi is also running Ollama.

    → Litter camera, cat

  11. Build the litter-cleanup automation

    Zone-entered and zone-cleared events from Frigate, a 10-minute cooldown, then a targeted Dreame zone clean — not a full-house run.

  12. Decide LLM hosting and add local voice

    Ollama on the Pi with a small model, offloaded to a spare GPU machine, or accelerated with an AI HAT+2. Install the Wyoming voice satellite (faster-whisper, Piper, openWakeWord). Confirm Home Assistant's local intent engine resolves simple commands before Ollama is ever consulted.

  13. Give it a memory, not a retrain

    A small local store (SQLite or a lightweight vector DB) that Ollama reads for household context — routines, the cat's usual schedule, preferences — read on every request, never used to fine-tune the model itself.

  14. Add remote access

    Tailscale. Confirm nothing is port-forwarded — check your router's forwarding table directly, don't just assume.

  15. Add the UPS and test it

    Router, switch, hub, and any radio dongles on it. NUT integration for monitoring, a shutdown automation at a set battery threshold, a load-shedding automation for the moment power drops. Then actually unplug it from the wall and confirm the whole chain fires.

  16. Validate end to end

    Pull the Ethernet cable and confirm Pi-hole and Tailscale behave as expected. Ask an Echo to do something simple and confirm it resolves through the local intent engine, not Ollama. Let the cat use the litter box and confirm the vacuum waits its ten minutes. This is the step that turns a diagram into a system you actually trust.

Closing notes

The build order above is the real answer to "how does this all come together" — everything else on this page is reference material for the steps in it.

  • Pi 5 (8GB) alone, or HA Green plus a second box for Frigate/Ollama — decide on purpose, not by default
  • VLANs, mDNS reflector, and DNS lockdown built before any device joins the network
  • Backups turned on before the first integration, not after the first scare
  • Ollama: on the Pi for a first build, offloaded to a spare GPU machine once it feels slow, or AI HAT+2 as a middle ground
  • Wyoming voice satellite (faster-whisper, Piper, openWakeWord) for local speech; local intent engine tried first, Ollama as fallback
  • Valetudo on the Dreame X only if your exact model is on valetudo.cloud's list; cloud room-cleaning otherwise
  • Frigate at 720p/5fps detection, tight zone polygons, Coral accelerator if sharing the Pi with Ollama
  • Remote access via Tailscale — never a forwarded port
  • UPS on the network gear and hub, monitored by NUT, tested by actually unplugging it
  • secrets.yaml for every token, no exceptions
